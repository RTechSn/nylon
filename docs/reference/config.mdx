## node.yaml

Each node has its own `node.yaml` with local settings. Generate a keypair with `nylon key`. Stdout is the private key, stderr is the public key.

```yaml title="node.yaml"
key: 0NcrMcaS1tORCTA88L5ZPE+H6yUMV4e5vRp6iypnPW8= # private key (from `nylon key`)
id: alice # must match this node's id in central.yaml
port: 57175 # UDP port nylon listens on

# --- Optional fields below ---

use_system_routing: false # if true, all peer packets exit via the TUN interface
no_tun: false # if true, run as a userspace-only relay without a TUN (requires use_system_routing: false and no addresses/prefixes for this node in central.yaml)
no_net_configure: false # if true, nylon won't touch system routes or interfaces
log_path: "" # write logs to this file (empty = stderr only)
interface_name: "" # override the interface name (default: "nylon", or utunX on macOS)
dns_resolvers: [] # DNS servers for nylon's own lookups, e.g. ["1.1.1.1:53"]
observability_addr: "" # e.g. "0.0.0.0:9090"; enables /metrics, /healthz, /readyz, and /discovery
mtu: 1420 # TUN interface MTU (omit for the device default 1420)
tun_queues: 4 # TUN queues drained in parallel (default: min(CPU count, 4)); Linux only
tun_txqueuelen: 10000 # kernel tx queue length per TUN queue (default: 10000; 0 = kernel default 500)
tun_backpressure: false # request IFF_BACKPRESSURE (default: false; requires kernel >= 6.15)
dynamic_prefixes_dir: "" # directory watched for dynamic prefix JSON files, e.g. /etc/nylon/prefixes.d (empty = disabled)

# Obf strategy listen mode: how the listen ranges DERIVED from the obf
# strategies your own advertised endpoints name (central.yaml) are served:
# "sockets" (default) binds one extra UDP socket per port, limited to 4096
# ports total; "nftables" keeps the single primary-port socket and installs a
# daemon-managed netfilter redirect per range (Linux, CAP_NET_ADMIN; no
# width ceiling). Ports themselves live on the strategies (central.yaml `obf:`)
# — the retired node-level listen_ports moved there.
listen_mode: "" # "sockets" | "nftables"; empty = sockets

# In-tunnel QoS: classify inner packets by protocol/port and keep small
# flows alive under bulk load. Matched flows ride ahead of bulk within
# in-device batches AND their outer (encrypted) datagrams are stamped with
# the rule's DSCP so a DSCP-aware WAN bottleneck can carry them past the
# bulk queue. medium/high/max map to in-device levels + default outer DSCP
# AF41/EF/CS7; dscp (0-63, optional) overrides the outer codepoint. The port
# matches either side of the flow (dport of requests, sport of replies);
# tcp/udp rules require a port, icmp rules match all ICMP/ICMPv6 and must
# not set one. Overlapping rules match in order (first wins), exact
# duplicates are config errors, at most 64 rules. The central config's lists
# win wholesale over these — first the router's own central entry, then the
# central top-level (mesh-wide) list. See guides/qos-priority.
priority_rules:
  - protocol: udp
    port: 5405 # or "5000-5100" for an inclusive range
    priority: high
  - protocol: tcp
    port: 22
    priority: high
    dscp: 46 # optional override of high's default EF

# Bootstrap: fetch central.yaml from a remote bundle on first start
dist:
  url: https://static.example.com/network1.nybundle
  key: 7PaN6DmAayz4KnDnsXSXJH+Oy0TFGeoM4FEbQfLriVY= # distribution public key
  interval: 1h # optional: fallback polling cadence (used while central.yaml's dist sets no interval)

# Split tunneling (per-node overrides)
exclude_ips: # add to the central exclude list
  - 192.168.0.0/24
unexclude_ips: [] # subtract from the central exclude list

# Lifecycle hooks (run in order)
pre_up: []
pre_down: []
post_up:
  - iptables -t nat -A POSTROUTING -s 10.0.0.0/24 -d 192.168.0.0/24 -j MASQUERADE
post_down: []
```

The `tun_*` fields size the TUN datapath and apply on Linux only; every other platform keeps the single-queue path. `tun_queues` drains the interface from several queues in parallel — the kernel steers each flow to one queue, so per-flow packet order is preserved and more queues mean more CPU parallelism for the drain. `tun_txqueuelen` is the kernel burst buffer the daemon reads from (one packet per unit, roughly 1.4 KB of kernel memory per queue at MTU 1420); it is programmed at interface creation and only takes effect when more than one queue is created. `tun_backpressure` asks the kernel to stop dropping when a queue is full and let the qdisc queue instead, trading dropped packets for added latency; it needs kernel >= 6.15 and is otherwise a silent no-op. Both counts are validated when the config is loaded: `tun_queues` must be 1–32 and `tun_txqueuelen` 0–1048576.

When you set `dynamic_prefixes_dir`, the nylon daemon watches that directory and announces prefixes from JSON files that local writers (scripts, Kubernetes sidecars, the nylon-lb agent) place there. See [Dynamic Prefixes](/reference/dynamic-prefixes) for the file contract.

## central.yaml

The central config defines the entire network topology. It is shared across all nodes (either copied manually or via config distribution).

```yaml title="central.yaml"
# --- Config Distribution (optional) ---
dist:
  # The distribution key is used to verify and decrypt sealed bundles.
  # Despite being called "public", treat it as a shared secret. It can decrypt your topology.
  key: 7PaN6DmAayz4KnDnsXSXJH+Oy0TFGeoM4FEbQfLriVY=
  # Nylon polls these URLs for config updates; the cadence defaults to 10s
  # and can be changed with `interval` (re-read live from config updates).
  repos:
    - file:central.nybundle          # local file
    - https://static.example.com/network1.nybundle # remote URL (HTTP GET)
  interval: 1h # optional: polling cadence; takes precedence over node.yaml's dist.interval

# --- In-tunnel QoS (optional, mesh-wide default) ---
# priority_rules at the TOP LEVEL is the mesh-wide default: every node
# (routers and clients alike) receives it through the distributed config.
# A router's own list (below) wins wholesale over this one, which wins
# wholesale over node.yaml. Same rule semantics as node.yaml's
# priority_rules (see node.yaml above and guides/qos-priority).
# priority_rules:
#   - protocol: udp
#     port: 5405
#     priority: high

# --- Routers ---
# Active nylon nodes that participate in routing and can forward traffic.
routers:
  - id: alice
    pubkey: xmfAovAKN4AY5ocK5s+/VsG9I27KrQ13Vzb0HOsLKAs=
    addresses: [10.0.0.1] # nylon interface addresses (auto-advertised as /32 or /128)
    endpoints:
      - "alice.example.com:57175" # domain name (re-resolved periodically)
      - "192.168.1.2:57175"       # LAN IP
      # Obf strategy tags: the ports come from the named strategies defined
      # in the top-level `obf:` map; untagged hosts default to ALL strategies
      # when the mesh defines any. Inline port ranges moved into strategies.
      # - "203.0.113.7[awg_main,hopping]"
      # - "198.51.100.9[*]"

    # In-tunnel QoS rules for THIS router: a non-empty list here wins
    # wholesale over the mesh-wide top-level priority_rules and over the
    # node's node.yaml priority_rules (an empty list is indistinguishable
    # from an absent one — configs roundtrip through yaml, which drops
    # empty lists). Same rule semantics as node.yaml.
    # priority_rules:
    #   - protocol: udp
    #     port: 5405
    #     priority: high
    prefixes:
      # Static: always advertised at the given metric
      - type: static
        prefix: 192.168.0.0/24
        metric: 0 # optional, default 0

      # Ping: advertised with RTT as metric, withdrawn after max_failures consecutive failures
      - type: ping
        prefix: 10.1.0.0/24
        addr: 10.1.0.8           # address to ping
        delay: 10s               # interval between pings (default: 15s)
        max_failures: 3          # failures before withdrawal (default: 3)
        bind_if: en10            # optional: bind to a specific interface
        # metric: 0              # optional: override RTT with a static metric (advertised unconditionally; suppresses failure retraction)

      # HTTP: advertised with request duration as metric, withdrawn on non-200 response
      - type: http
        prefix: 10.2.0.0/24
        url: http://example.com/healthz
        delay: 15s               # interval between probes (default: 15s)
        # metric: 5              # optional: override request duration with a static metric

  - id: bob
    pubkey: 4GfHHSyVpXc+wkbjyIIONERa6Xf5EafB0nVGZLf2r2o=
    addresses: [10.0.0.2, 10.1.0.2] # multiple addresses are fine
    endpoints:
      - "192.168.1.1:57175"
      - "nylon.example.org" # port defaults to 57175 (the nylon default port)

  - id: eve
    pubkey: 2mXTTD+FYdtJm/v1vSHz8qimvCucjW9vY+nLYacXJFE=
    addresses: [10.0.0.3]
    # no endpoints. eve can only connect outward to nodes that have endpoints

  - id: public
    pubkey: dJcUE1qnXCQ5x8pMhFb/MZab7YrBaaHcrgfbmQI0MW4=
    addresses: [10.0.0.4]
    endpoints:
      - "123.123.123.123:57175" # multiple endpoints; nylon picks the best one dynamically
      - "123.123.123.124:57175"

# --- Clients ---
# Passive WireGuard clients that don't run nylon. Only static prefixes allowed.
clients:
  - id: client1
    pubkey: SBI+yvF30Ba4xo0GKTtKHSSfbXAnRNFTBwydJyJp6Rk=
    addresses: [10.0.0.7]
    prefixes:
      - type: static
        prefix: 192.168.1.0/24 # also add this to AllowedIPs in the WireGuard client config

# --- Split Tunnel ---
# Excluded prefixes are NOT routed through nylon (network-wide default).
# Per-node overrides are in node.yaml (exclude_ips / unexclude_ips).
#
# How the layers combine (applied per-node):
# 1. Start with all prefixes from the routing table
# 2. Drop: prefixes this node itself originates (exact match only --
#    learned more-specifics inside them still install)
# 3. Subtract: central exclude_ips (below)
# 4. Add back: node unexclude_ips
# 5. Subtract: node exclude_ips
#
# Example: central excludes 10.0.0.0/8. Node "alice" sets
# unexclude_ips: [10.1.0.0/16] -- re-includes 10.1.x.x
# exclude_ips: [10.1.99.0/24] -- but not 10.1.99.x
# Result for alice: 10.1.0.0/16 is routed through nylon, except 10.1.99.0/24.
# All other 10.x.x.x traffic bypasses nylon.
exclude_ips:
  - 192.168.0.0/24

# --- Dynamic Prefix Ranges ---
# Receiver-side allowance for prefixes.d announcements: receivers accept an
# announced prefix when it falls inside one of these ranges (prefixes already
# listed under routers[] remain routable regardless). Each range must be a
# valid, masked prefix (no host bits). Empty = fail-closed: only prefixes
# known from this central config are routable.
dynamic_prefix_ranges:
  - 10.0.0.0/8

# --- Obfuscation ---
# The global obf block — the network-wide obfuscation half (upstream naming:
# the central obf block serves the whole network; a per-node obf block would
# hold per-node parameters, and in this fork everything per-node lives in
# the named strategies instead). It carries the mesh-wide AmneziaWG 2.0
# handshake dialect (S/H) inline — the wire contract every pair of nodes
# must speak identically, so it cannot vary from node to node — plus the
# named strategy map under `strategy:`. Omit the whole block for vanilla
# WireGuard-compatible behavior. The values below are examples; generate
# one with `nylon-genesis`.
obf:
  s1: 32
  s2: 28
  s3: 20
  s4: 16
  h1: # header range: min must not exceed max
    min: 100
    max: 5000000
  h2: # header ranges must not overlap each other
    min: 10000000
    max: 200000000
  h3:
    min: 400000000
    max: 800000000
  h4:
    min: 1000000000
    max: 2100000000
  # Strategy selection for new connections (which obf strategy carries each
  # connection): fixed (the first strategy of the endpoint's list) | random
  # (a random strategy per connection) | trial (iterate randomly until a
  # connection establishes, then prefer the confirmed strategy; re-search on
  # failure). REQUIRED when the mesh defines more than one strategy.
  strategy_mode: trial
  # Named obf strategies: each entry bundles the ports a node listens on /
  # connects through, the client-side rotation policy for those ports, and the
  # sender-local junk (jc/jmin/jmax and i1-i5). Endpoints reference strategies
  # by name — the strategy name is its identity:
  #   endpoints:
  #     - "hub.example.com[hopping,vanilla]"
  # Untagged endpoints (or "[*]") mean "every defined strategy".
  strategy:
    awg_main:
      ports: "40000"      # required: one port or an inclusive range "40000-50000"
      jc: 5               # sender-local junk: 5 datagrams of size [250, 800)
      jmin: 250           # ahead of every handshake initiation
      jmax: 800
      i1: <b 0xc0ff><r 8><t><r 40> # optional CPS specs; empty ones are omitted
    hopping:
      ports: "40000-50000"
      port_hopping_mode: timed   # static (default) | reactive | proactive | timed
      port_hopping:              # knobs; which matter depends on the mode
        period_seconds: 30
        period_jitter_pct: 1
    vanilla:
      ports: "51820"

# --- Graph ---
# Defines which nodes will peer with each other. Only nodes connected in the graph
# will attempt to establish WireGuard tunnels.
#
# IMPORTANT: The graph controls direct peering only. Two nodes that are NOT
# directly connected in the graph can still communicate. Their traffic is
# forwarded through intermediate nodes that ARE connected.
graph:
  # Groups: a shorthand for sets of nodes (nodes within a group are NOT auto-connected)
  - Group1 = alice, bob
  - Group1, Group1           # connect every node in Group1 to every other node in Group1
  - Group2 = Group1, client1 # groups can contain other groups
  - client1, eve, alice      # all three fully interconnected

# Updated automatically by `nylon seal`; used as a version number for config distribution.
timestamp: 1740832962209309000
```

A `metric` override behaves differently per check type. On a `ping` entry the value is advertised unconditionally from startup and suppresses failure retraction, so the prefix stays announced even when the probe target is down; leave it unset if you want health-driven withdrawal. On an `http` entry the override replaces only the healthy request-duration metric, and failures still retract. See [Dynamic Prefixes](/reference/dynamic-prefixes) for the full behavior.

The mesh-wide S/H dialect (inline in `obf:`) and the strategies' `jc`/`i1`–`i5` junk params are normally produced by `nylon-genesis`, which picks viable header ranges automatically. See [Obfuscation](/guides/obfuscation) for the wire-format background and [Genesis](/guides/genesis) for the generation workflow.

## Obf Strategies

Strategies are the multi-level named list inside the global `obf:` block (`obf.strategy:` in `central.yaml`). They are mesh-wide definitions; endpoints select among them per-host.

| Field               | Type   | Default    | Notes                                                                                                                      |
| ------------------- | ------ | ---------- | -------------------------------------------------------------------------------------------------------------------------- |
| `ports`             | string | required   | one port (`"40000"`) or an inclusive range (`"40000-50000"`)                                                                 |
| `jc`                | uint   | omitted    | sender-local junk datagrams sent ahead of every handshake initiation; requires the `jmin`/`jmax` size range, and the strategies a node uses must agree on the whole junk set (see the wire reality below) |
| `jmin`, `jmax`      | uint   | omitted    | junk datagram size range `[jmin, jmax)` — equal bounds give fixed-length junk; `jmin` must not exceed `jmax`                  |
| `i1`-`i5`           | string | omitted    | CPS packet specs such as `<b 0xc0ff><r 8><t><r 40>`; only non-empty specs are emitted to the device                        |
| `port_hopping_mode` | string | `static`   | rotation strategy for the strategy's ports: `static` \| `reactive` \| `proactive` \| `timed`                                 |
| `port_hopping`       | map    | omitted    | rotation knobs (`budget_packets`, `period_seconds`, `period_jitter_pct`, `recent_ports`, `cooldown_seconds`, `candidate_samples`, `recycle_seconds`) — same semantics as the pre-reform node-level block |

**Listen half**: a node binds the union of `ports` over every strategy its OWN advertised endpoints name (untagged = all strategies), served per `listen_mode`. The primary port (`node.yaml`'s `port`) is always bound.

**Connect half**: every tagged endpoint of a peer expands into one candidate set per named strategy; the carrying endpoint's strategy supplies the rotation policy.

**Strategy selection** (`obf.strategy_mode`): decides WHICH strategy carries each new connection — every drawn carrying endpoint is one connection (one UDP flow through the middleboxes), so the mode applies on every draw. Orthogonal to `port_hopping_mode`, which decides WHEN the carrying endpoint rotates *within* the selected strategy's ports.

| Value    | Behavior                                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `fixed`  | every connection uses the FIRST strategy of the endpoint's list (config order: endpoints first, then the tag order as written) |
| `random` | every connection draws a random strategy, preferring one other than the outgoing connection's when the endpoint names more than one |
| `trial`  | iterate randomly until a connection establishes (the carrying endpoint is heard back on — the handshake completed); the confirmed strategy is remembered, and every later connection — reconnects and rotations alike — first uses it. A carrying-link death (the same liveness model that drives reactive rotation) condemns the memory: the reconnect still retries the strategy first, and only a second death without a confirmation in between demotes it — the random iteration resumes |
| `rated`  | reserved: strategy rating by measured connection performance — parses, but validation rejects it as not implemented yet                              |

The mode is required when the mesh defines more than one strategy (this build replaced the former implicit behavior — rotations drew across all strategies uniformly — with an explicit choice, like `port_hopping_mode` before it), and dead config when the mesh defines none. An explicit tag list is the operator's preference order: `fixed` pins the first as written, while untagged hosts and `[*]` use the strategies in sorted (map) order.

**Wire reality**: the AWG 2.0 device speaks exactly ONE handshake dialect (the mesh-wide S/H inline in `obf:`) and emits ONE junk configuration — the `jc`/`jmin`/`jmax` stream plus one I-packet set, sent toward EVERY peer, not per strategy. The strategies a node uses (its own and its peers' advertised endpoints) must therefore share a single junk set — validation rejects conflicting `jc`/`jmin`/`jmax` or `i1`-`i5` with the strategies named. A strategy without junk params simply emits no junk. Receivers discard junk unclassified, so two nodes may still draw their junk from different strategies.

**Migration** (config reform): `listen_ports`, `port_hopping_mode` and `port_hopping` at node/router level, per-node `obf:` blocks, and inline endpoint port ranges moved into strategies; the old keys still PARSE but fail validation with pointers, and inline ranges in endpoints are rejected at parse time with the same migration message. The strategy `protocol` label and the `jc`/`jmin`/`jmax` trio on the mesh-wide profile were dropped in the same reform — the strategy NAME is the identifier, and the junk trio moved onto the strategy itself. The intermediate `awg_profile:` top-level key (the first reform draft) folded into `obf:` — nest `s1`–`s4`/`h1`–`h4` directly under `obf:` and strategies under `obf.strategy:`; strict decoding rejects the old placement with an unknown-field error.

## Endpoints

Three forms exist (IPv6 hosts bracketed as usual: `[2001:db8::1]:51820`, `[2001:db8::1][strats]`):

| Form                  | Meaning                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------ |
| `host:port`           | raw fixed-port endpoint, no strategy; a stock configured link                                     |
| `host`                | bare host: every strategy's ports when the mesh defines any, else the default port (57175)          |
| `host[s1,s2]`         | strategy-tagged: the ports come from the named strategies, in the written order (the preference order `strategy_mode: fixed` pins); `host[*]` is the same as untagged |

Inline port ranges (`host:30000-40000`) moved into strategies and are rejected with a migration error; combining an explicit port with tags (`host:9000[s1]`) is a contradiction and is rejected too.

## Dynamic Prefixes (prefixes.d)

Setting `dynamic_prefixes_dir` in `node.yaml` (recommended: `/etc/nylon/prefixes.d`) enables a watcher that announces prefixes from JSON files in that directory:

```json title="/etc/nylon/prefixes.d/10-vip.json"
{
  "version": 1,
  "prefixes": [
    { "type": "static", "prefix": "10.99.0.1/32", "metric": 0 }
  ]
}
```

The contract:

- `version` must be `1`; `prefixes` entries use the same `type` values and keys as the central `prefixes` list (`static`, `ping`, `http`).
- Adding or updating a file announces its prefixes; removing it withdraws them.
- Invalid JSON or an unsupported version skips the whole file; a single invalid entry skips only that entry.
- Files apply in lexicographic filename order; a duplicate prefix across files resolves to the entry from the earlier filename.
- Use one writer per file, and write to a temp file followed by an atomic rename (the temp name must not end in `.json`).
- On the receiving side, announcements are gated by central `dynamic_prefix_ranges`.

See [Dynamic Prefixes](/reference/dynamic-prefixes) for the full contract and examples.

## Naming Rules

Node IDs (`routers[].id`, `clients[].id`) must:
- Match `^[0-9a-z._/-]+$`
- Be at most 100 characters
- Be unique across all routers and clients

Group names used in `graph` are folded to lowercase, must not equal a node name, and must be unique. The strict node-ID pattern above is not applied to them.
